简单的二分查找，最关键的一点在数组两边是否都能取。

本题比较简单，是 [] 类型数组，两端都可以取到，所以循环退出条件为 <= ，如果是 (] 或者 [) 类型的数组，那就不能是等于了，而且后面 if 里面的分支也要改变，也就是删掉那个 +1 或者 -1 。

---

<br>

> ### 🤖 AI 补充

<br>

「开闭」指的不是数组，而是 `left` 和 `right` 这两个下标谁能被取到：

- `[]` 闭区间：`nums[left]` 到 `nums[right]` 全部有效
- `[)` 左闭右开：`nums[left]` 有效，`nums[right]` 取不到，`right` 只是「右边界的后一个位置」
- `(]` 左开右闭：`nums[left]` 取不到，`left` 只是「左边界的后一个位置」

三处必须一起改，只改 if 分支会出错：

| 区间 | 初始化 | 循环条件 | `nums[mid] < target` | `nums[mid] > target` |
|---|---|---|---|---|
| `[]` | `left=0, right=n-1` | `left <= right` | `left = mid+1` | `right = mid-1` |
| `[)` | `left=0, right=n` | `left < right` | `left = mid+1` | `right = mid` |
| `(]` | `left=-1, right=n-1` | `left < right` | `left = mid` | `right = mid-1` |

哪一端是开的，就往哪一端去掉 ±1。所以 `[)` 删的是 `right` 那边的 `-1`，`(]` 删的才是 `left` 那边的 `+1`。

为什么初始化也要改：`nums=[1,3,5]` 找 `5`，用 `[)` 写法但初始化还是 `right=n-1=2`，则 `mid=1` 时 `3<5` 让 `left=2`，然后 `left<right` 即 `2<2` 不成立，直接退出返回 -1，最后一个元素根本没被检查。必须 `right=n=3`，`right` 才能指到数组外面那个「后一个位置」。

`(]` 还有个坑：`mid=(left+right)/2` 是向下取整，可能算出 `mid==left`，这时走 `left=mid` 就等于原地不动，死循环。所以 `(]` 必须写成向上取整 `(left+right+1)/2`。这也是大家一般用 `[)` 不用 `(]` 的原因：向下取整天然安全。

另外 `[)` 退出循环时 `left==right`，这个位置自始至终没被检查过，所以循环外面还得补一句 `nums[left] == target`。而 `[]` 靠 `left <= right` 保证每个位置都查到了，循环里返回就行，不用补。

Go 的 int 是 64 位，本题 n ≤ 10000 不会溢出。换成 Java/C 的 32 位 int，`(left+right)/2` 在极端情况会溢出，要写成 `left+(right-left)/2`。
